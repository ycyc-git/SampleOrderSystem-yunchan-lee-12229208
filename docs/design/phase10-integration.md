### 예약 재고(reservedStock) 모델 검증

Phase 10에서 도입된 재고 관리 모델:

| 이벤트 | `sample.stock` (가용) | `sample.reservedStock` (예약) |
|--------|---------------------|------------------------------|
| 주문 승인 (재고 충분) | −qty | +qty |
| 주문 승인 (재고 부족) | −available (→ 0) | +available |
| 생산 완료 (tick) | +(actualQty − shortage) | +shortage |
| 출고 (release) | 불변 | −qty |
| 재큐 (requeueToProducing) | +반환 후 재예약 | −반환 후 재예약 |

- 신규 주문 분석 시 `currentStock = sample.stock` (예약분 제외)
- 모니터링 `pendingDemand` = RESERVED 주문 quantity 합계 (CONFIRMED/PRODUCING 제외)

### ANSI 컬러 일관성 점검

| 요소 | 컬러 |
|------|------|
| 메인 현황 숫자 값 | 노란색 / 초록색 |
| 주문 상태 배지 | RESERVED(파랑), CONFIRMED(초록), PRODUCING(주황), RELEASE(보라) |
| 재고 상태 배지 | 여유(초록), 부족(주황), 고갈(빨강) |
| 생산라인 상태 배지 | RUNNING(주황), IDLE(회색) |
| 완료 메시지 ("예약 접수 완료.", "출고 처리 완료." 등) | 초록색 |

### 엣지케이스 점검 목록

- [ ] 모든 메뉴에서 잘못된 번호/문자 입력 시 재시도
- [ ] 숫자 필드에 문자 입력 시 파싱 오류 없이 재입력 요청
- [ ] RESERVED 목록이 빈 경우 "[3] 주문 승인/거절" 진입 처리
- [ ] CONFIRMED 목록이 빈 경우 "[6] 출고 처리" 진입 처리
- [ ] 생산 큐가 빈 경우 "[5] 생산라인 조회" 진입 처리
- [ ] 동일 주문을 두 번 승인하려는 경우 (CONFIRMED 상태에서 재선택 불가)

## 수동 테스트 시나리오 — 전체 통합

```
시나리오 1 — 재고 충분 전체 흐름
1.  시료 등록: S-001, 0.5 min/ea, 0.92, 초기재고 200
2.  주문 접수: S-001, 고객A, 80ea
3.  주문 접수: S-001, 고객B, 60ea
4.  [4] 모니터링 → RESERVED 2건, 재고 200 여유 확인
5.  [3] 주문 승인/거절 → 고객A 80ea 승인 → CONFIRMED, 재고 120 확인
6.  [3] 주문 승인/거절 → 고객B 60ea 승인 → CONFIRMED, 재고 60 확인
7.  [6] 출고 처리 → 고객A 출고 → RELEASE, 재고 여전히 60
8.  [4] 모니터링 → CONFIRMED 1건, RELEASE 1건 확인

시나리오 2 — 재고 부족 전체 흐름 (시연 모드, 초 단위)
1.  시료 등록: S-002, 0.3 min/ea, 0.78, 초기재고 0
2.  주문 접수: S-002, 고객C, 100ea
3.  [3] 주문 승인/거절 → 재고 부족, 실생산량/총시간 확인 후 승인 → PRODUCING
4.  [5] 생산라인 조회 → 진행률 바 실시간 갱신 확인
5.  생산 완료 후 [4] 모니터링 → CONFIRMED 전환 확인
6.  [6] 출고 처리 → 출고 → RELEASE 확인

시나리오 3 — 거절 + 모니터링
1.  주문 접수 후 [3] 주문 승인/거절 → [N] 거절
2.  [4] 모니터링 → 거절 건수 표시 안됨 확인

시나리오 4 — 복합 (두 주문 동시 생산 큐)
1.  S-001, S-002 재고 0 상태에서 각각 주문 → 모두 승인 → PRODUCING 2건
2.  [5] 생산라인 조회 → 현재 처리 중 1건 + 대기 큐 1건 확인
3.  첫 번째 완료 → 두 번째 자동 시작 확인
```
